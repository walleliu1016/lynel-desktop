# 定时任务（Tasks）页面重设计

- 日期：2026-09-21
- 状态：设计稿（待评审，未实施）
- 涉及文件：`components/tasks/*.vue`、`stores/tasks.ts`、`utils/tasks.ts`、`styles/theme.css`
- 不改动：`src/main/tasks/*`（主进程契约、SQLite 表结构、IPC 全部保持）

---

## 1. 现状与问题

| # | 问题 | 具体表现 |
|---|---|---|
| P1 | 文本输入太多 | 新建任务要打 3 样东西：名称、整段 prompt、cron 表达式。prompt 往往上百字且必须手写绝对路径 |
| P2 | 空态是空白 | 详情页默认什么都不显示，必须点一次运行历史里的某一行才看到流水；从未运行过的任务更是纯空 |
| P3 | 运行历史平铺 | 详情页纵向堆「键值块 → 运行历史列表（带分页）→ 流水」，历史一长就把主要内容挤到屏幕外 |
| P4 | 视觉朴素 | 详情页没有工具栏层级；行高与间距靠各处手写；`.btn` 在 4 个组件里各定义一份 |
| P5 | 状态靠颜色 | 启停/失败只有 6px 圆点 + 颜色，不满足「不能只靠颜色传递信息」 |

---

## 2. 目标

1. **用鼠标完成 80% 的配置**：模板卡片承担 prompt，时间用下拉承担键盘输入，cron 退到「高级」。
2. **打开即有内容**：选中任务后主体默认渲染最近一次运行的完整流水。
3. **历史收进按钮**：工具栏一个「历史」按钮，点开列表、点行切换，不再与正文抢纵向空间。
4. 在不新增设计 token 的前提下做出层级（沿用 `styles/theme.css` 现有变量）。

### 3.1 工具栏（新增）

一行，`position: sticky; top: 0`，`background: var(--bg-panel)` + 下边框。

- 左：状态点 + 任务名（超长省略，`title` 给全名）
- 中右：**分段切换** `[运行] [历史 · 23]` —— 两个段都常显，行内数字是运行次数徽标
- 右：主按钮 `[▶ 立即执行]`（`--accent`）、溢出菜单 `[⋯]`（编辑 / 复制为新任务 / 删除）

> 「编辑 / 删除」从现在的图标并排收到溢出菜单里：工具栏只保留一个主操作，降低误触删除的概率。

### 3.2 摘要条（新增）

一行 caption，`·` 分隔：调度摘要、下次运行（含「今天/明天」相对文案）、上次运行状态与相对时间、上次费用。

数据全部来自现有 `TaskDto`（`schedule` / `nextRunAt` / `lastRunAt` / `lastStatus`），**无需改主进程**。

### 3.3 主体

单个滚动容器，由工具栏的分段决定渲染哪一个：

- **运行模式**（默认）：`RunStreamView`，渲染当前 `activeRunId` 那次运行。
- **历史模式**：运行历史列表。

## 4. 关键行为改动

### 4.1 默认显示最近一次运行（P2）

`stores/tasks.ts` 的 `select(id)` 在 `loadRuns(false)` 之后**自动选中首页第一条 run 并拉取事件**：

```ts
async function select(id: string) {
  activeTaskId.value = id;
  activeRunId.value = null;
  events.value = [];
  runs.value = [];
  runsHasMore.value = false;
  await loadRuns(false);
  const latest = runs.value[0];
  if (latest) await openRun(latest.id);   // ← 新增：默认展示最近一次
}
```

同理 `remove` / 首次 `load` 后也走这条路径。`RunStreamView` 的换 run 逻辑（重置展开态、历史 run 从顶部读）已经存在，直接复用。

**从未运行过**的任务：不显示空白，显示引导卡片：

```
        ┌────────────────────────────────┐
        │             [play]             │
        │        这个任务还没运行过        │
        │   点「立即执行」跑一次，结果会显示在这里 │
        │           [▶ 立即执行]          │
        └────────────────────────────────┘
```

### 4.2 历史收进按钮（P3）

历史模式是一张列表，每行（点击整行）：

```
✓ 成功  自动  09-21 09:00  修复了 3 个失败的 job            8轮 · 1m20s · $0.031  ›
✗ 失败  自动  09-20 09:00  超出最大轮次限制                12轮 · 3m02s · $0.088  ›
◷ 中断  手动  09-19 14:12  用户取消                          4轮 · 0m41s · $0.014  ›
[ 加载更早的运行记录 ]
```

- 状态用 **pill（图标 + 文案 + soft 底色）**，不再是纯色圆点 → 解决 P5。
- 行右侧的 `RunStreamView` 里已有的 `runSummaryText` / `formatDuration` 直接复用。
- 点击某行 → `openRun(id)` + 切回运行模式。

### 4.3 运行模式的「这是哪一次」

运行卡片头部保留 `RunStreamView` 现有状态栏，只补两处：

- 头部左侧加时间戳（`09-21 09:00`）与触发方式（自动 / 手动）。
- 当 `activeRunId !== runs[0].id` 时，头部右侧出现 `回到最新` 文字按钮。

### 5.1 模板（P1 的主力）

新增渲染层纯数据文件 `utils/taskTemplates.ts`：

```ts
export interface TaskTemplate {
  id: string;
  name: string;              // 卡片标题
  icon: string;              // Icon.vue 已注册的键
  blurb: string;             // 一句话说明
  presetName: string;        // 名称默认值（可被 appendSchedule 覆盖）
  prompt: string;            // 含 {{path}} 槽位
  needsPath: boolean;        // 是否必须先选目录
  defaultPreset: Preset;     // 例如 { kind: 'daily', hour: 9, minute: 0 }
}
```

候选模板（6 个，具体清单待定，见 §8）：

| 模板 | 默认调度 | 需要目录 |
|---|---|---|
| CI 失败巡检 | 每天 09:00 | 是 |
| 每日变更摘要 | 每天 18:00 | 是 |
| 依赖安全审计 | 每周一 09:00 | 是 |
| 清理构建产物 | 每周五 18:00 | 是 |
| 依赖升级 | 每月 1 日 10:00 | 是 |
| 空白任务 | 每天 09:00 | 否 |

选中模板后：填名称、填 prompt（`{{path}}` 用当前目录替换，未选则原样留着并在提交时拦截）、设好调度预设，用户**只剩时间需要确认**。

### 5.2 名称：默认自动生成

名称输入框改为「自动生成 / 手动输入」两态：

- 自动态（默认）：`模板名 · 每天 09:00`，随调度变化实时更新，输入框显示为只读灰字。
- 点一下输入框 → 转手动，可编辑；清空则回到自动态。

这样「名称」不再是一个必填项，`canSubmit` 里对 name 的校验相应放宽（自动态恒有值）。

### 5.3 时间：下拉而非输入

- 时：`00–23` 下拉；分：`00/05/10/…/55` 下拉（步进 5，避免 60 个选项）。
- 每周：7 个可点方块（保留现状）。
- 每月：日 `1–31` 下拉。
- 每 N 分钟：`5/10/15/20/30/45` 下拉 + 「自定义」。
- **cron 表达式输入框折叠进「高级」**，默认收起。预设改动不再回填可见的表达式框（只有展开高级时才显示），去掉现在「表达式框实时跟手」带来的噪声。

`buildExpr` / `detectPreset` 逻辑**原样保留**（与主进程 `presetToCron` / `cronToPreset` 的模板必须有第二份实现这一点不变），只是被折叠到高级里。

### 5.4 「插入目录路径」

prompt 里的绝对路径靠手打是最痛的输入。做法：prompt 输入框下方一个 `[folder] 插入目录路径…` 按钮，弹出目录选择器（复用 `files.ts` 已有的目录能力 / 或直接调 Electron 的 `dialog.showOpenDialog`），选中后把**绝对路径文本**插入 prompt 光标处，并替换 `{{path}}` 槽位。

> 注意：这**不**引入「项目 / 工作目录」概念 —— 执行 cwd 仍是常量 `tasks_dir`，路径只是 prompt 里的一段文本。UI 文案必须避免「在哪个项目运行」这种措辞。

## 6. 视觉规范（P4 / P5）

全部使用 `styles/theme.css` 既有变量，**不新增 token、不改配色**。

| 项 | 规范 |
|---|---|
| 工具栏 | 高 44px，`padding: 0 16px`，sticky，`--bg-panel` + `1px --border` |
| 摘要条 | 高 34px，`--fs-caption`，`--text-secondary`，`--bg-primary` |
| 分段控件 | pill 容器 `--bg-input` + 选中段 `--bg-panel` + `--shadow-card`，段高 26px |
| 状态 pill | `[图标 12px][文案]`，soft 底色（`--status-success-soft` / `--status-error-soft` / `--accent-soft-bg` / `--bg-hover`），`--radius-pill` |
| 历史行 | 高 38px，左侧 4px 状态色条（`border-left`），hover `--bg-hover`，选中 `--bg-selected` |
| 卡片 | `--bg-card` + 1px `--border` + `--radius-md`；结果卡片用 `--status-success-soft` / `--status-error-soft` |
| 焦点 | 所有可交互元素补 `:focus-visible { outline: 2px solid var(--border-focus); outline-offset: 2px }` |
| 动效 | 仅用 `background/opacity` 过渡，150ms；**不得**依赖动画传达状态（本机系统动画已关闭） |
| 图标 | 一律 `Icon.vue` 已注册的 lucide 键；新增键要先在 `Icon.vue` 补 import + 映射 |
| 空态 | 一律「图标 + 一句说明 + 一个动作」，禁止纯空白（P2、a11y `empty-states`） |

### 6.1 消除重复（DRY）

`.btn` / `.btn.primary` / `.btn.ghost` 目前在上游 4 个任务组件里各写一份（`TaskList` / `TaskDetailPane` / `TaskFormDialog` / `RunStreamView`）。本次抽到 `styles/components.css`（或 `theme.css` 末尾的组件层），四个组件删掉本地定义。

## 8. 待确认

1. **模板清单**：上表 6 个是我按「定时任务常见用途」拟的候选；实际要哪些、prompt 具体怎么写，需要按你真实的使用场景定。也可以先只做「空白任务 + 2 个模板」，留出扩展位。
2. **「插入目录路径」**：做还是不做？不做的话 prompt 里的绝对路径仍需手打（最痛的一块输入）。做的话需要一个目录选择 IPC，且文案要小心不要暗示「项目」概念。
3. **历史入口形态**：本文选「工具栏分段切换」（最贴合「一个按钮点击切换」）。备选是「右侧滑出抽屉」——视觉上更分层，但与现有 `TracePane` 的全屏子页风格不一致，且要多写一层遮罩/入场动效。
4. **`detailView` 归属**：放 Pinia store（跨组件、切 tab 保留）还是 `TaskDetailPane` 本地 ref（切任务自动重置）。倾向前者，与 `activeSubTab` 的现有做法一致。

## 9. 不做什么（YAGNI）

- 不做任务分组 / 标签 / 优先级。
- 不做运行结果的对比视图（两次 run diff）。
- 不做拖拽排序任务。
- 不改主进程的调度、存储、IPC 契约。
- 不引入新的配色方案或字体（若引入，需同时改浅色/深色两套 token，收益不抵成本）。
