3运行流水（基于实测样本）

用本机真实样本驱动：claude -p "…" --output-format stream-json --verbose，claude 2.1.114，一次带 Bash 调用的完整往返共 9 行。 结构上最关键的一点：assistant 是「一个 content block 一行」，同一 message.id 被拆成多行（该样本 4 条 assistant 行只有 2 个 id），必须先按 message.id 分组才是「一条消息」。 工具调用默认折叠成一行 StepCard（照 magic-slash 的做法），顶部一排按元素显隐开关（照 @fnclaude/renderer 的做法）。

实测推翻的 5 处假设 —— 渲染层必须按这些来写

  1. assistant 不是「一条消息一行」，是一个 content block 一行；同一 message.id 跨多行。→ 先按 message.id 分组再渲染，不能按行边界切消息。
  2. 不要假设 tool id 前缀。实测是 call_00_1wClu5X4x87ixrpzM3Wr1570（第三方 base_url），不是 toolu_。→ 显示只取末 4–8 位，配对只做等值比较。
  3. tool_result.content 是多态的：实测为纯字符串（"total 724\n…"），也可能是 block 数组或 null。→ 三态归一化后再渲染。
  4. system 事件不止 init：实测流开头两行是 hook_started + hook_response（全局 settings 的 SessionStart hook 在无头下照样触发）。→ 降级成一行，不能当未知事件丢弃。
  5. usage 不是扁平 token map：含 server_tool_use{} / cache_creation{} / iterations[] 等嵌套对象与字符串字段。→ 按白名单挑数值字段，直接 Object.entries 会渲染出一堆 [object Object]。
另外三个实测细节：空的 thinking block 真实存在（{"type":"thinking","thinking":"","signature":"…"}）必须过滤，否则渲染空卡片； mcp_servers 会带 status:"failed"，应提示用户； 一次 ls -la 就花了 $0.165（input 28k，几乎全是 cache read），所以成本必须显眼——每个 run 都要显示。
