## 0.0.14

### 新功能

- **在线升级（auto-update）**：设置页新增"在线升级"tab，支持从 GitHub Releases 或私有 HTTP 云服务检测并下载新版本。
  - **双源 fallback**：优先 GitHub API（`/repos/latest`）获取版本信息，云服务地址已配置时作为 fallback（`/api/update/check?platform=&arch=&version=&channel=stable`）。`latest.yml` 仅作为 sha512 辅助，缺失不阻塞检测。
  - **新模块 `src/main/updater/`**：
    - `checker.ts` — 双源版本检测，GitHub API 10s 超时 + HTTP fallback 10s 超时，失败原因具体到每个源
    - `downloader.ts` — 临时 `latest.yml` → `autoUpdater.setFeedURL(file://)` → `checkForUpdates()` → `downloadUpdate()` → `quitAndInstall()`
    - `index.ts` — 注册 4 个 IPC handler（`app:checkUpdate` / `app:downloadUpdate` / `app:quitAndInstall` / `app:getUpdateStatus`），启动 5s 后首次检查，之后每 4h 定时检查
    - `types.ts` — `CloudCheckResponse`、`CheckResult`、`UpdateState`、`UpdateConfig` 接口定义
  - **新组件 `UpdaterTab.vue`**：显示当前版本、检查更新按钮、更新通道说明、状态/进度/下载/强制更新弹窗。云服务地址复用云服务菜单已有配置，不单独暴露输入框
  - **`electron-builder.yml`** 添加 `publish.github` 配置（`provider: github, owner: walleliu1016`）
  - **仅 stable 通道自动更新**，beta 需手动下载安装

- **权限全局绕过**：每个 session 启动时创建的临时 `settings.json` 自动注入 `"permissions": { "defaultMode": "bypassPermissions" }`，所有 Claude 会话不再弹出权限审批

- **登录错误信息具体化**：`desktopSocket.login()` 返回具体错误原因（网络连接失败、DNS 解析错误、超时、HTTP 401/403/404/5xx、API 返回的 error 字段透传），不再统一显示"请检查用户名和密码"

### 改进

- **企业微信通知**：移除所有消息中的时间戳显示（`HH:mm`），消息更简洁

### 改进（补充）

- **Hook 配置迁移到临时 `settings.json`**：每个 session 启动时创建独立的临时 settings 文件并注入 hook 配置，新增 `continueOnError: true` 避免 hook 异常中断 Claude 运行；设置 tooltip 显示实际生效的 settings 路径
- **流式期间 UI 卡顿**：消除全链路放大效应——之前每个 stage 事件会触发多次 store 更新 + 终端渲染 + trace 推送，流式输出高峰时主进程和前端同时进入忙等，UI 明显卡顿。改为批量合并 + 节流
- **企业微信 WS 连接状态可见**：断连、重连、恢复、重连耗尽各状态流转统一通过 ToastCenter 通知用户，节流避免刷屏

### Bug 修复

- **`/screenshot` 截图渲染失败：`require is not defined`**：commit 452fb17 把 `@napi-rs/canvas` 改为 `require()` 懒加载避免 Intel Mac 启动崩溃，但项目是 ESM (`type: module`) 没有全局 `require`，所有平台截图都失效。改用 `createRequire(import.meta.url)` 构造 ESM 兼容的 require
- **企业微信卡片消息 WS 断连后永久发送失败**：`wsClient.on('close')` 监听的事件 SDK 永远不发（SDK 实际发的是 `'disconnected'`），导致 `entry.wsClient` 永不被清理；`connectBot` 重连时不先断开旧实例，旧实例的 SDK 内部重连与新实例竞争同一 botId 被企微服务器反复互踢。修复：事件改 `'disconnected'`，`connectBot` 先 `disconnect` 旧实例
- **企业微信 WS 永远不能自动恢复**（上一个问题的延伸）：
  - `disconnected` 不再清空 `entry.wsClient`：保留引用让 SDK 内部自动重连成功后 `authenticated` 回调直接恢复 `isConnected`
  - `authenticated` 区分首次认证 / SDK 自动重连恢复 / 陈旧实例顶替三种场景，陈旧实例立即 `disconnect()` 丢弃
  - 新增 `scheduleReconnect` 主动重连兜底：断连 30s 起步、指数退避至 5 分钟封顶，SDK 自身已恢复时该 timer 自动取消
  - `WS_RECONNECT_EXHAUSTED` 时清空 wsClient + 通知用户"已离线" + 触发主动重连
  - `ensureBotWebSocket` 在 `await connecting` 后二次检查 `isConnected` 消除竞态
  - `disconnectAll` / `updateBots` 清理 `reconnectTimer` 避免游离 timer 泄漏
- **electron-updater 在测试环境构造 `autoUpdater` 时崩溃 `app.getVersion` 为 undefined**：`downloader.ts` 模块顶层访问 `autoUpdater` getter 触发 `new NsisUpdater/MacUpdater` 构造，构造函数读 `app.getVersion()`，vitest 无 Electron runtime 抛错。改为 `getAutoUpdater()` 懒加载，仅在 IPC 调用真正下载/安装时才触发构造
- **session 关闭时未通知 cloud**：关闭 session 后 cloud 端仍保留 stale session 状态

### 清理

- **删除孤儿文件**：`SettingsView.vue`（Login 场景旧设置页）、`WelcomeView.vue`（已废弃欢迎页）、`wailsjs/` 目录（迁移到 Electron 后的遗留代码）
