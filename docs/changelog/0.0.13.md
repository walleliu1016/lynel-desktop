## 0.0.13

### 新功能

- **外部交互错误统一通知中心**：所有主进程与外部（云服务、企业微信 Bot、SSE、本地文件、桌面 socket）的失败现在统一在主窗口右侧悬浮堆叠弹窗展示，5s 自动关闭、可手动 × 关闭、hover 暂停倒计时、多条时按时间从上往下追加、间隔 10px，上限 6 条，超过按入栈顺序丢弃最旧。
  - **新模块 `src/main/channels/notify-error.ts`**：`notifyExternal({ source, level, message })` 统一封装，按 `error 5s / warn 10s / info 不限` 节流，避免断网场景下同一错误刷屏；`errMessage(err)` 辅助从任意 Error 抽取 message。bus emit 异常时静默（通知是辅助能力，不应阻塞主流程）
  - **新组件 `src/renderer/src/components/ToastCenter.vue`**：右侧 `top: 56px` 悬浮（避开 36px TitleBar），`width: 360px`，左侧 3px 色边按 level 配色（`--status-error / --status-warn / --accent`），左 Icon 组件（`AlertCircle / AlertTriangle / Sparkles`），右 × 关闭按钮，`<TransitionGroup>` 实现"新条目从右侧滑入、旧的下移"动效。容器 `pointer-events: none` + 单条 `pointer-events: auto` 不阻挡其他点击
  - **`useToast.ts` 重写为模块单例**：`pushToast({ level, source, message, duration })` API；`pauseToast(id) / resumeToast(id)` 给 hover 暂停用；1s 同 `(level, source, message)` 去重；旧 `showToast` 标 `@deprecated` 保留，App.vue 不再渲染旧 div
  - **payload 协议**：`getBus().emit('app:toast', JSON.stringify({ level, source, message, duration? }))`，前端 `useEventStream` 优先解析 JSON，兼容旧两参数 `(level, message)`
  - **接入面**（全部走 notifyExternal）：
    - `wecom-channel`：插件加载、Bot 连接、6 类事件推送（user/agent/tool-call-start/tool-call-end/service）、3 类卡片（permission / AskUserQuestion / ExitPlanMode）、核心 `sendContent`
    - `cloud-channel`：envelope / hook flush 与非 2xx 响应
    - `sse-channel`：客户端 write 失败
    - `desktop-socket`：`/api/auth/login` 失败、disconnect 异常、`emit()` 在 `!connected / !authenticated` 静默丢时（30s 节流）、`connect_error`（30s 节流）、`reconnect_failed`（不节流）
    - `registry`：`dispatch / dispatchHook / closeAll` 错误隔离
  - **前端 17 处 showToast 调用全部迁到 pushToast**：覆盖 SessionItem、AppearanceTab、ChannelTab、BotManagement、GeneralTab、ProviderTab、XtermTerminal，按业务域标 `source: 'session' / 'settings' / 'channel' / 'bot' / 'terminal' / 'provider'`，失败时显示原 error message（如 `操作失败：xxx`），成功用 `level: 'info'`

- **权限待审批时窗口注意力信号**：仿 QQ 行为——主窗口不在前台（前台 = `visible && !minimized && focused`）时，权限请求到达按平台分支触发注意力信号；任一渠道（主窗/企微/灵动岛/cloud）resolve 时自动停闪
  - **新模块 `src/main/attention.ts`**：`windowAttention` 单例，订阅 `PermissionBroker.onRaise / onResolve / onCancel`，维护 pending 集合 + 派生 project 名（`path.basename(workDir)`）+ 截断 workDir
  - **按平台分支**：
    - Windows: `BrowserWindow.flashFrame(true)` 任务栏闪烁
    - macOS: `app.dock.bounce('informational')` 仅"0 → 非 0"弹一次 + `app.setBadgeCount(n)` 角标
    - Linux: `app.setBadgeCount(n)`
    - 全部平台: `new Notification({ title, body, silent: false })` 系统通知，标题 `Lynel Desktop · 权限待审批`，正文 `工具名\n项目：xxx\n目录：xxx`；同会话 30s 节流
  - **托盘动态化**（`createTray` 抽 `rebuildTrayMenu(entries)`）：
    - tooltip 跟 pending count 变（`Lynel Desktop · N 个权限待审批`）
    - 菜单加 `待审批 (N)` 不可点项 + 最多 5 条子项（`工具名 · 项目名`，点击聚焦对应 session）
    - `显示主窗口` 项走新 `focusMainWindow`：强制 `moveTop + flashFrame(false) + focus` 前置
  - **通知/托盘点击 → 切 tab**：emit `attention:focus-session` 带 `{ sessionId, workDir, projectName, toolName }`，前端 `useEventStream` 订阅调 `tabs.openSession` + `sessions.select`；点击处理加 `restore + show + moveTop + flashFrame(false) + focus` 五件套强制 z-order
  - **修复 Windows 通知显示 "Electron"**：`package.json` 加 `productName: "Lynel Desktop"`，`index.ts` 启动时 `app.setName('Lynel Desktop') + setAppUserModelId('com.lynel.desktop')`

### Bug 修复

- **CI 打的 x64 dmg 在 Intel Mac 启动抛 `Cannot find native binding`**：`build.yml` 用 `npx electron-builder --mac --x64` 直接调，绕过 `npm run dist:mac` 脚本里的 `pre-dist-mac.mjs`，导致 macos-latest (arm64) runner 上只装 `@napi-rs/canvas-darwin-arm64`，x64 dmg 缺 `@napi-rs/canvas-darwin-x64` 子包，Intel Mac 用户 `require('@napi-rs/canvas')` 时 js-binding 找不到原生模块崩溃
  - 修复：`.github/workflows/build.yml` mac 任务加 `if: matrix.target == 'mac'` 的 `Pre-build: install opposite-arch canvas native binding` 步骤，CI 在 Build installer 之前先跑 `node scripts/pre-dist-mac.mjs` 补齐缺失架构的子包

- **`desktop-socket.emit()` 静默丢消息不通知**：mock 停止 / cloud 不可达时，socket 永远停在 `connecting / disconnected / reconnecting`，所有 envelope/hook/session 推送在 `if (!this.socket?.connected)` / `if (state !== 'authenticated')` 直接 return + warn，用户完全感知不到。在两个早 return 点加 `notifyExternal`（30s 节流）

- **`PermissionBroker.onRaise` 之前没被业务订阅**：权限请求从未走注意力链路，windowAttention 永远拿不到 pending。`app.ts` init 阶段补 `permissionBroker.onRaise` hook，调用 `windowAttention.onPermissionRequest({ id, sessionId, workDir, toolName })`

- **cloud 下行事件 JSON stringify 导致字段全 undefined**：cloud 端 `socket.emit` 时将 payload `JSON.stringify` 了，desktop 收到的是 string 而非 object，`data.session_id`、`data.question`、`data.request_id` 等字段全部返回 `undefined`，`desktop:chat` 消息被静默丢弃、`desktop:hook:result` 权限结果无法匹配。全域 4 个 cloud→desktop 事件 (`auth:success`、`auth:failed`、`desktop:hook:result`、`desktop:chat`) 统一改用 `(...args: any[])` 参数 + `typeof raw === 'string'` 检测 + `JSON.parse` 防御。

- **PermissionToast `id`/`requestId` 字段名不一致导致权限弹窗从未显示**：`app.ts` 发出 `permission:request` 事件时字段是 `id`，但前端 `HookPermissionRequest` 接口、`useEventStream` 校验、`SessionTabContent` 读取都用 `requestId`，永远不匹配，`setHookPermission` 从未被调用。统一为 `id`。同时禁用终端内 PermissionToast 覆盖弹窗，权限审批走 WeCom 卡片或终端直接处理。

- **`createConsoleFallback()` scope 无限递归爆栈**：原实现 `scopeImpl` → `scopedFallback` → `base[level]`（即 `tagged(level)`）→ 又调 `base[level]`，形成自循环，任意 scope 链式调用即爆栈崩溃。改为 scope 返回的 logger 调用 `root[level]` 底层写流函数，`scope().scope().scope()` 任意嵌套不再递归。新增 `tests/main/log-fallback.test.ts` 验证。
