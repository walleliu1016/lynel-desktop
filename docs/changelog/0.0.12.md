## 0.0.12

### Bug 修复

- **关闭/重启后 `--resume` 找不到 conversation**：`createSessionInternal` 用 `randomUUID()` + `--session-id` 启动时，Claude 的 jsonl 是懒创建的（要发首条 prompt 才落盘），但 lynel 立即把 sid 写进 `recent-sessions.json`，导致用户在发 prompt 前关闭/重启后留下"phantom session"。本次修复：
  - `App.openTerminal` 加 jsonl 存在性检查，缺失时 fallback 到 `PtyMode.New` + 同 sid 重新拉起（jsonl 路径不变），规避 `No conversation found with session ID` 错误
  - `createSessionInternal` 末尾的 `addRecentSession` 改为延迟到 hookserver 收到首个 `UserPromptSubmit` 事件后再写，从源头消除 phantom session 进入 recent 列表

- **企业微信 markdown 消息超长 40058**：企微对单条 markdown 消息硬限制 20480 字节，长 tool result / 长 agent 文本会触发 `errcode=40058 body.markdown.content exceed max length 20480`。`WeComChannel.sendContent` 入口加长度检查，超过 19000 字符（保留 ~1.5KB buffer 应对 JSON 序列化膨胀）时自动截断并标注"内容过长已截断 N 字符"

- **企业微信 `/screenshot` 终端截图渲染错乱**：`renderBufferToPng` 此前有 4 个 bug 导致截图与终端实际显示不一致：
  1. `rawBuffer.replace(/\r/g, '\n')` 把单独 CR 替换为 LF，破坏 spinner/进度条等"行首覆盖"重绘语义
  2. headless xterm 硬编码 `rows: 100`，与 PTY 实际 rows（通常 24）不一致，光标定位序列和 `\x1b[J` 擦除错位产生大片空白
  3. `if (width === 0 || !chars) continue;` 跳过时不推进 `xPixel`，后续 cell 位置偏左，右侧边框被截断
  4. 早期版本试图用 `findLastSgrReset` + `slice(lastReset)` 规避截断颜色泄漏，但会截掉前面所有内容导致截图几乎空白

  修复：直接 `term.write('\x1b[0m' + rawBuffer, ...)`（前置 reset 重置 headless 起始状态），`rows` 接受 `opts.rows` 并从 `session.getSize()` 透传 PTY 实际尺寸，渲染循环分情况推进 `xPixel`（`!cell` 推进 `charWidth`，`width === 0` 跳过宽字符第二列，`!chars` 视作空格推进 `cellPixelWidth`）

### 新功能

- **企业微信发送失败 toast 告警**：`WeComChannel.sendContent` 包裹 `sendFn` try-catch，发送失败时通过 `getBus().emit('app:toast', 'error', ...)` 推送告警到前端，前端 `useEventStream` 已订阅 `app:toast` 事件并 `showToast`，无需前端改动。告警信息包含 sessionId 前 8 位 + 错误信息前 100 字符。仍保留 `throw err` 让外层 `.catch` 不丢感知

- **Cloud 上行 API 接口**：`CloudChannel` 接入两个云服务接口（见 `docs/desktop-interfaces.md`）：
  - `POST /api/envelope/push`：envelope 批量推送，buffer + 3s 定时合并窗口（满 50 条提前 flush），减少 HTTP 请求数
  - `POST /api/sessions/sync`：会话元数据同步，在 session 创建、打开终端、adopt 时触发
  - `app.ts` 新增 `syncCloudSession()` 辅助方法，从 `readRecentSessions()` 取 title 构建 SyncSession，含 `jsonl_path`、`cwd`、`project_name`、`last_activity_at`
  - `CloudTab.vue` 测试连接改为 `POST /api/health`，mock server 同步新增三个端点

- **Hook 事件上行 + PermissionRequest 同步 forward**：`CloudChannel` 实现 `HookChannel`，接入第三个云服务接口 `POST /api/hook`：
  - **非审批 hook**（PreToolUse/PostToolUse/SessionStart/Stop/UserPromptSubmit 等）：fire-and-forget 批量上行，3s/50 条，与 envelope 流量解耦
  - **PermissionRequest**：同步 forward 到云端等待决策（默认 2h 超时），cloud 响应原样透传给 Claude；本地 broker 先 resolve 时 POST `action=abort` 通知云端取消（同时取消本地 fetch）
  - body 统一格式：`{ action: 'forward'|'abort', from: 'desktop', data: <hook body>, request_id?, decision? }`
  - `HookEventLike` 加 `rawBody?` 字段承载 Claude 原始 hook body；`PermissionHandler` 返回类型加 `rawResponse?`，hookserver 存在时原样透传给 Claude
  - `app.ts` onPermissionRequest 入口协调 cloud + broker race：cloud 胜 -> 透传 + resolve broker；broker 胜 -> cloud abort + 本地 decision；cloud 报错/超时 -> 清理后继续等 broker

- **企业微信 `/screenshot` 与 `/help` 控制指令**：
  - 新增 `src/main/terminal-screenshot.ts` 模块：`stripAnsi()` 清洗 SGR/OSC/CUU 等控制码，`renderBufferToPng()` 用 `@xterm/headless` 解析 PTY 原始 buffer + `@napi-rs/canvas` 渲染为 PNG（深色主题，保留 ANSI 颜色与 box-drawing 边框）
  - `wecom-channel` 新增 `__screenshot__` / `__help__` sentinel 路由，`handleScreenshot()` 复用现有会话路由（引用 -> bot 绑定 -> 默认映射）-> 取 buffer -> 渲染 PNG -> `uploadMedia` + `sendMediaMessage` 推送到企业微信
  - 失败时回复文本告知原因（bot 未连接 / 会话不存在 / buffer 空 / 渲染失败 / 上传失败），不抛异常
  - 详见 `docs/superpowers/specs/2026-07-23-terminal-screenshot-wecom-design.md`

- **Cloud 通信从 HTTP 切换到 Socket.IO**：`DesktopSocket` 取代 `CloudChannel` 的所有 HTTP 调用，统一走 Socket.IO 长连接（保留 `POST /api/auth/login` 换 JWT）：
  - 新增 `src/main/channels/desktop-socket.ts`，实现 `OutputChannel` + `HookChannel` 双接口
  - 上行事件：`desktop:auth` / `desktop:session:sync` / `desktop:envelope:push` / `desktop:hook:batch` / `desktop:hook:permission` / `desktop:hook:abort`
  - 下行事件：`auth:success` / `auth:failed` / `desktop:hook:result` / `desktop:chat`（Mobile 转发的消息路由到对应 session PTY）
  - 认证流程：启动时读本地 JWT（`settingsStore.cloud_jwt`）-> 有 JWT 直接 `desktop:auth` -> 失效时 `POST /api/auth/login` 用 App 解锁密码换 JWT -> 拿到后持久化 + emit `desktop:auth`；socket 重连自动重走该流程
  - envelope buffer 3s/50 条，hook buffer 3s/50 条，PermissionRequest 同步等待 `desktop:hook:result`（默认 2h 超时），本地 race 胜出时 emit `desktop:hook:abort` 通知 cloud 取消
  - `app.ts` 注入 `JwtPersistence` 回调读写 `cloud_jwt`，App 解锁时缓存明文密码供 cloud login 使用，锁定时清空
  - 密码校验仅在 cloud 启用时做，未启用时 `app:verify` / `app:isInitialized` 直接返回成功；cloud 未启用时不建立 Socket.IO 连接
  - `CloudTab.vue` 去掉"鉴权 Token"输入框，状态显示改为 2s 轮询 socket 状态（disconnected/connecting/connected/authenticated/auth_failed）
  - `scripts/mock-cloud-server.cjs` 改造为 Socket.IO 服务端，命令行支持 `allow`/`deny`/`list`/`chat`/`help`/`exit`
  - 修复 4 个对接问题：
    1. transports 从 `['websocket']` 改为 `['polling', 'websocket']`，避免 Electron 下纯 websocket 握手失败
    2. `app:setPassword` 首次设置密码时缺密码缓存 + `applyCloudSettings` 触发，导致 desktop-socket 始终无密码可用
    3. 前端 `Verify` IPC 返回 false 时未走 `SetPassword` 兜底（`ipcRenderer.invoke` 不因返回 false 而 reject），`stores/auth.ts` 显式判断返回值
    4. `desktop-socket` 未注册为 `HookChannel`，补 `dispatcher.registerHook(this.desktopSocket)`，否则 hookserver 的 hook 事件不会转发到 cloud

- **登录页集成云服务配置**：原方案要求用户先点"设置" -> CloudTab 启用云服务才能登录，入口隐蔽。本次将云服务开关搬到登录页：
  - `LoginView.vue` 在密码输入框下方加 Switch 开关 + 服务地址输入框 + 提示文案（"开启后，会话消息与权限请求将实时推送到移动 App，便于远程审批与查看进度"）
  - 开关切换时窗口高度自动调整（基础 400 + 开启后 +120），避免内容超出把登录按钮挤出可视区域
  - `onMounted` 读 `GetSettings()` 预填已保存的配置，已配置用户默认勾选 + 预填 URL
  - `onSubmit` 先调 `UpdateCloudSettings(enabled, url)` 写 settings.json，再走 `auth.login` -> `app:verify` / `app:setPassword` 触发 cloud 重连
  - 新增 `app:cloud:updateSettings` IPC：保存 `cloud_service_enabled` + `cloud_service_url`，URL 变更时清掉旧 JWT（cloud 实例变了，旧 JWT 必然失效）
  - 启用云服务时 URL 必填，否则登录按钮禁用
  - `preload.ts` + `useElectron.ts` 暴露 `updateCloudSettings` / `UpdateCloudSettings` 转发层

- **主页标题栏云服务连接状态指示器**：在使用指南按钮右侧加状态药丸，仅 `cloud_service_enabled = true` 时显示：
  - 2s 轮询 `app:cloud:connectionState` IPC（与 CloudTab 一致）
  - 状态映射：已连接（绿色，authenticated）/ 认证中（黄色脉冲，connected）/ 连接中（黄色脉冲，connecting）/ 认证失败（红色，auth_failed）/ 未连接（灰色，disconnected）
  - hover title 显示完整文案"云服务：xxx"

### 关闭流程资源泄露修复

长时间运行 UI 卡住、关闭后重启偶发 `Network Error: read ECONNRESET` 的根因：关闭流程多处资源泄露，PTY/apiproxy/hookserver 未真正释放。

- **`window:quit` 绕过 shutdown**：标题栏关闭按钮直接 `process.exit(0)`，`before-quit` 不触发，PTY 子进程成为孤儿、apiproxy/hookserver listening socket 被 OS 强制 RST。改为 `app.quit()` 走完整关闭流程
- **`before-quit` async 不被 await**：Electron 同步事件不 await async 回调，`shutdown()` 来不及完成。改为 `event.preventDefault()` + 异步 shutdown 完成后 `app.exit(0)`
- **apiproxy `close()` 不关 keep-alive 连接**：`server.close()` 等待 keep-alive 自然结束（永不结束），进程退出时 OS 发 RST -> claude CLI 抛 `read ECONNRESET`。加 `server.closeAllConnections()`，`close()` 改 async 返回 Promise
- **hookserver `stop()` 被 SSE 悬挂**：SSE 长连接永不 end，`server.close()` 回调永不触发。`stop()` 加 `closeAllConnections()`；shutdown 顺序调整为先 `sseChannel.close()` 结束所有 SSE Response，再 `hookServer.stop()`
- **PTY onExit 不清理 apiproxy**：`apiProxies` 数组里残留死亡 proxy（占端口、占 Buffer、占 jsonl 句柄）。`wirePty` onExit 中查找并 `close()` 对应 proxy，从 `apiProxies` 移除
- **shutdown proxy.close 改并行 await**：`Promise.all(this.apiProxies.map(p => p.close()))` 确保 listening socket 真正释放

### Cloud 连接与登录验证修复

- **cloud socket `Invalid namespace` / 404**：URL 带反代路径前缀（如 `https://host/lynel`）时，socket.io-client 把整个 URL 当 namespace；服务端 socket.io 挂在根路径 `/socket.io`。改为连接 origin + 默认 path `/socket.io`，HTTP API 仍用完整 URL
- **登录后停在"认证中"**：`updateConfig` 中 socket 已连接但停在 `connected`（未认证）时，密码从无到有不触发重试。加 `ensureJwtAndAuth` 重试逻辑，用户解锁后立即用新密码换 JWT
- **错误密码也能登录**：`auth.login` 不区分首次设置与验证，`Verify` 返回 false 时统一走 `SetPassword` 覆盖，错误密码被当成新密码设置成功。改为先查 `IsInitialized`，已初始化时只走 `Verify`，失败直接报"密码错误"
- **登录页 cloud status 干扰**：TitleBar 加 `hideCloud` / `hideLogout` prop，登录页隐藏 cloud status 与退出登录按钮
- **cloud status 简化**：`connected` 显示为"已连接"（不再"认证中"），socket 连接即视为成功
- **CloudTab 去掉"测试连接"按钮**：移除 `/health` 探测按钮与 `testStatus` 状态机，仅保留连接状态显示
- **退出登录按钮**：TitleBar 用户信息区加 log-out 图标按钮，触发 `app:logout` IPC 清密码 + cachedPassword + 断开 cloud socket，HomeView 跳转回登录页
